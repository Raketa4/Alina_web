## 3. Технический подход

- Чистый статический сайт: HTML + CSS + ванильный JS. **Без сборки, без CI.**
  Деплой — загрузка файлов в репозиторий (как в проекте `raketa4.github.io`).
- Плоские HTML-файлы в корне репозитория. Все ссылки на ресурсы —
  относительные (`assets/…`, `css/…`, `js/…`, `data/…`), чтобы сайт
  одинаково работал в подкаталоге `/Alina_web/` и позже на своём домене
  в корне.
- Контент-данные — в JSON (`data/`), страницы рендерятся из них на JS.
- Двуязычность: словари `i18n/ru.json`, `i18n/en.json`, применяются по
  атрибутам `data-i18n` / `data-i18n-attr`. В HTML-разметку заранее вписан
  русский текст (для поисковиков и работы без JS). Переключатель RU/EN в
  шапке; выбор языка хранится в `localStorage` и отражается в `?lang=`.
- Репозиторий: `https://github.com/Raketa4/Alina_web`, локальная копия
  `c:\Users\Андрей\Alina_web`. Ветка `main`.

## 5. Приём заявок (без бэкенда)

Кнопка «Оставить заявку» у работы формирует `mailto:`-ссылку с темой вида
`Заявка: «Название работы», 2019, 40×58 см` и телом-шаблоном (имя,
способ связи, вопрос). Форма контактов работает так же: собирает поля в
текст письма и открывает почтовый клиент. Рядом — явные ссылки на
Telegram и соцсети как альтернатива. Сторонних сервисов нет.

## 6. Визуальное направление (Valentino + академизм)

- **Типографика:** заголовки — Cormorant Garamond; основной текст —
  EB Garamond; меню, подписи, служебные подписи — Inter, верхний регистр,
  разрядка. Все гарнитуры с кириллицей, подключение с Google Fonts, с
  системными фолбэками (`Georgia, 'Times New Roman', serif` и
  `system-ui, sans-serif`).
- **Палитра (CSS-переменные):**
  - `--bg` тёплый галерейный белый `#F7F5F1`
  - `--ink` тёплый чёрный `#1E1B18`
  - `--accent` оксблад/бордо `#6E1E24`
  - `--canvas` нейтральный «холст» `#B8A99A`
  - `--rule` тонкие линии `#E2DBD0`
  - Один светлый режим, тёмной темы нет (галерейный сайт).
- **Макет:** узкая фиксированная шапка (слева знак, справа меню в
  разрядку, крайний правый — переключатель языка); много воздуха;
  крупная издательская подача изображений; тонкие горизонтальные
  линейки; подписи мелким трекингом капсом. При наведении — лёгкий зум
  изображения и проявление подчёркивания у ссылок.
- **Анимация:** минимальная — мягкое проявление блоков при скролле через
  `IntersectionObserver`, отключается при `prefers-reduced-motion`.
- **Логотип:** шрифтовой знак «АЛИНА ХОНЯК / ALINA KHONIAK» на Cormorant;
  монограмма «АХ / AK» в `favicon.svg`. Это и есть «разработка логотипа»
  для Фазы 1.

## 7. Данные и ассеты

```
data/site.json      контакты, соцсети, e-mail, ID счётчиков (пусто → выключено)
data/projects.json  [{ slug, title{ru,en}, year, description{ru,en}, cover, images[] }]
data/catalog.json   [{ id, title{ru,en}, year, medium{ru,en}, size, price?, status, project, image }]
data/cv.json        { education[], teaching[], exhibitions[], awards[], publications[] } со значениями {ru,en}
i18n/ru.json        словарь интерфейса (ключ → строка)
i18n/en.json        тот же набор ключей → перевод
assets/works/<slug>-full.jpg  (~1600 px по большей стороне)
assets/works/<slug>-thumb.jpg (~800 px по большей стороне)
assets/photos/artist-portrait.jpg
assets/logo.svg, favicon.svg, favicon-32.png, apple-touch-icon.png
```

- `status` ∈ `available` | `reserved` | `sold`.
- `price` необязателен; если отсутствует — на карточке «Цена по запросу».
- Плейсхолдеры изображений генерирует `scripts/make-placeholders.mjs` —
  с точными пропорциями и именами из JSON, чтобы замена сводилась к
  перезаписи файла.
- Каталог стартово заполняется 12 работами серии «Горы и море» (данные с
  Vigbo). «Портреты» — 3 позиции без деталей, помеченные «уточнить».

## 8. SEO и аналитика

- На каждой странице: уникальные `<title>`, `meta description`,
  `<link rel="canonical">`, OG/Twitter-теги, JSON-LD
  (`Person`/`VisualArtist` на `about.html`, `WebSite` на `index.html`).
- `robots.txt`, статический `sitemap.xml` (7 страниц + страницы проектов
  с query-параметром), `hreflang` на `?lang=ru` / `?lang=en`.
- `js/analytics.js`: сниппет Яндекс.Метрики + подготовка под GSC; ID
  берётся из `site.json`, при пустом значении скрипт ничего не грузит.
  HTML-файл верификации GSC кладётся в корень при получении. Короткая
  заметка о приватности в футере и на `info.html`.

## 9. Проверки (вместо тест-фреймворка)

`scripts/check.mjs`, запуск `node scripts/check.mjs`. Проверяет:

1. Полное совпадение набора ключей между `i18n/ru.json` и `i18n/en.json`.
2. Валидность JSON и соответствие схеме всех файлов в `data/`.
3. Каждый путь к изображению из `data/*.json` существует в `assets/`.
4. Все внутренние ссылки между HTML-страницами резолвятся в
   существующие файлы.

Проверки пишутся до реализации соответствующих модулей (TDD).
`scripts/make-placeholders.mjs` — вспомогательный, покрывается проверкой 3.
